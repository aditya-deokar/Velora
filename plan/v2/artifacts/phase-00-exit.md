## 00.1 Package identity

- `VELORA_PACKAGE` in `src/core/branding.ts` is the single source of truth.
  - It is registered as a canonical owner; the frozen-metadata rule is generalized in `scripts/check-architecture.mjs`, with a competing-owner fixture.
  - The guide exposes `capabilities.package`.
- **Maintainer edit honored:** `legacyNames` is `['velora']` only (`@webprodigies/velora` dropped).
- Consumers now routed through it:
  - generated Vite adapter (`vite.ts`)
  - portable/Next wrapper (`portable.ts`)
  - toolkit lookup, install hints, VELORA.md text and dev-server identity check (`commands.ts`)
  - dependency allowlist (`services.ts`)
  - guide example and API text (`authoring.ts`)
  - `ERR_TOOLKIT_MISSING` hint (`cli-schema.ts`)
- **Design decision:** an installation under only the earlier `velora` name is now `missing-installation`, with the exact `npm install @adityadeokar/velora` command. Generated adapters import the scoped preview entry, and accepting a legacy-only install would produce imports that cannot resolve. Legacy names are used only to recognize and upgrade earlier installer bytes.
- **Legacy upgrade:** `init` rewrites earlier generated bytes in place, and user-edited files are still refused.
  - Vite path: preview adapter (incl. the old TSX-only glob) and VELORA.md.
  - Portable/Next path: the managed connection.
  - `load`/`validate` report `incomplete-setup` ("run velora init to upgrade") instead of a generic conflict.
  - Real-world proof: `npm run setup:local` upgraded the committed `local-project`. `ProjectPreview.tsx` and `VELORA.md` were rewritten and the stale `velora` file dependency replaced. `local-project` then type-checked and built against `@adityadeokar/velora`.
- Scripts, fixtures, skills, templates, examples, demo hosts and the agent-trial binding all use the scoped name.
  - `check-agent-trial.mjs` normalizes via `VELORA_PACKAGE`; the original trial hash still verifies.
  - Recorded demo pixel SHAs are unchanged (`test:agent-demos` green).
- Docs: README maintainer section, `docs/product.md`, `docs/architecture.md`, USER_GUIDE.

## 00.2 Frame cache sees host edits

- `hostFingerprint(root)` (export services) is a stat-only hash of what can change pixels:
  - code, styles and markup anywhere;
  - images, video and fonts under source/asset dirs;
  - the lockfile.
- It excludes dependency, build, dot and output dirs, render manifests, compositions, audio and captions. Compositions are excluded so timeline edits keep cache hits, as demo A relies on.
- It also excludes `src/velora/scenes`, which is already keyed per scene, so editing one scene still re-renders only that scene (existing test kept green).
- Above 20k files, that command renders uncached.
- `frameCacheKey` gains `hostSha`.

## 00.3 Bounded-memory video render

- `renderTimelineFrames` takes a `spill` sink. Video renders write each frame to a project-scoped `.velora-video-*/frames` sequence and keep metadata only.
- `encodeFrameBuffers` streams the sequence back one frame at a time, with identical FFmpeg args and output.
- Evidence: 20 s 1920×1080 at 60 fps, 1,200 frames, uncached, via the installed CLI.
  - Peak working set: **191 MB**.
  - Wall time: 156 s.
  - Exit 0; temp directory removed.
  - The scene was visually flat (small PNGs). The bound is structural and asserted by `tests/export/video-memory.test.ts`.

## Open findings (not fixed in this phase)

- **UTF-8 BOM:** JSON files written with a BOM (Windows PowerShell 5.1, Notepad) are rejected as "Invalid composition JSON". Recommend stripping a leading `U+FEFF` in project/discovery reads, with a test. A small fix for Phase 01 or a patch release.
- `scripts/npm-cmd.mjs` triggers Node's DEP0190 warning (`shell: true` with args) on Windows. It is harmless today; consider quoting or `cmd.exe /c` before Node removes the behavior.
- Release step for the maintainer: bump to `0.1.3` across package.json, every `skills/velora*/SKILL.md` front-matter `version` and `skills-lock.json`, then `verify:release`, then push.
