## Backward compatibility

- Every new field is optional with no default, so existing recipes parse to the same output and evaluate byte-identically.
- Proof: `tests/core/fixtures/motion-golden.json` was generated by the **pre-change** evaluator (extracted from `HEAD`) over all 24 committed recipes at 25 sample times. `tests/core/motion-v2.test.ts` asserts exact equality.
- Intentional output changes (documented in the CHANGELOG):
  - GSAP conversions now map to the precise family instead of `cinematic`/`easeInOut`.
  - `wipe-mask`/`iris-mask`/`mask-reveal` emit clip tracks instead of travel+fade.
  - `MotionState` carries `channels`.

## Deviations from the phase file

- `EasingSchema` is not a registered canonical owner: the checker requires object-rooted schemas, and this is a union. `applyEasing` (the evaluator) is the registered owner instead.
- `useChannel` returns the fallback for a channel with no track but emits no advisory diagnostic. Deferred, because it needs a consumed-channel registry in the Scene.
- VS Code autocomplete through `$schema` was not exercised manually. Schemas are generated, shipped and drift-tested.
