## What shipped
| Task | Implementation |
|---|---|
| 03.1 Vocabulary | New owner `src/core/edit.ts`. `EditOpSchema` is a discriminated union on `op` covering keyframes (`key.set` upsert, `key.remove`, `key.move`, `key.ease`, `keys.shift`, `keys.scale`, `keys.reverse`), tracks (`track.add`, `track.remove`, `track.options`), scene base (`camera.set`, `focus.set`, `node.ensure`, `node.remove`, `motion.set`, `look.set`), structure (`clip.create`, `clip.update`, `clip.dissolve` with optional bake, `stagger.set`, `link.set`, `link.remove`, `constraint.set`, `constraint.remove`, `path.fromAxes`, `path.tangent`), metadata (`editor.set`), the inverse primitive `restore`, and the Phase 12–16 ops reserved as `ERR_EDIT_UNSUPPORTED`. Tracks are addressed by `{target, property, clip?}` and keyframes by `(track, atMs)`, never by array index. `applyEdits` is atomic over raw recipe JSON; results must pass `SceneRecipeSchema` **and** `presentPreview` (no second validator). Issue paths name the op (`ops.3:definition.motion…`), and a past-duration keyframe gets a `motion.set` hint. A new surface or style track adds its node automatically (recorded in the inverse). Also `coalesce`, `describeOp`, `parseTrackShorthand` and `lineDiff`. |
| 03.2 Writer | `formatJsonDocument` (new owner in `src/core/json.ts`): a span-tracking parser; unchanged subtrees copied verbatim (including large snapshot data URLs); changed containers keep their inline or multi-line layout, spacing, indentation, CRLF, BOM and trailing-newline state; LCS alignment of array elements; existing key order kept, with added keys placed by the value's own order (so restores return home) or canonical schema order for trailing additions. Fresh values use same-shaped templates from the document, then a sibling, then an optional `reference` text; values inside an inline container stay inline. Numbers use shortest round-trip form. |
| 03.3 CLI | `velora edit ls\|apply\|key\|ease` (new owner `executeEditCommand` in `src/project/edit.ts`, commands layer): dry run by default (diff, labels, validation, inverse); `--write` uses `atomicWrite` compare-and-swap against the read SHA; `--expect-sha` fails fast; `--ops -` reads stdin; an envelope's `inverse` can be applied directly. Error catalog: `ERR_EDIT_INVALID`, `ERR_EDIT_CONFLICT`, `ERR_EDIT_TARGET`, `ERR_EDIT_UNSUPPORTED`, `ERR_BRIDGE_PORT`, `ERR_BRIDGE_HOST`. Added `CLI_COMMANDS` entries, `--help` text and REFERENCE rows. |
| 03.4 Bridge | `velora edit [--scene] [--port] [--read-only] [--no-open] [--url]` verifies the dev server through the existing `open-preview` check, binds `127.0.0.1`, creates a 256-bit token, and opens `<preview URL>&velora-scene=<id>&velora-edit=1#velora-bridge=<port>.<token>` (the token stays in the fragment only). Transport in `src/project/services/bridge.ts` (bridgeServices layer): `GET /v1/hello`, `GET /v1/scenes/:id`, `POST /v1/scenes/:id/edits` (200 `{sha, inverse}` / 409 `{sha, text}` / 422 `{issues}`), and `GET /v1/events` (text/event-stream: `ready`, `file-changed`, `bridge-closing`). Idle shutdown after 30 minutes with no editor connected. The bridge keeps up to 64 recent revisions per scene, so an undo batch that recreates a known revision writes that exact text. |
| Security | Loopback bind only (0.0.0.0, :: and LAN hosts are refused); bearer token compared in constant time over SHA-256 digests and never accepted in query strings (400) or logged; exact Origin allowlist (others get 403 with no CORS headers; preflight answered only for the allowed origin, including `Access-Control-Allow-Private-Network`); Host must be `127.0.0.1:<port>`, `localhost:<port>` or `[::1]:<port>` (421 otherwise); body ≤ 1 MB (413), ≤ 2,000 ops (413), JSON content type only (415); scene ids by slug, paths through `scopedPath` (traversal is 404, a symlink is 403); compare-and-swap atomic writes; `--read-only` returns 405; JSON-lines audit log with path, SHAs before and after, and labels. |
| 03.5 Watcher | `watchProjectFiles`: `fs.watch` on `src/velora/scenes`, `src/velora/presets` and the root (`*.composition.json`), debounced 100 ms per file. Temporary atomic-write names fold onto the real file, and an unchanged SHA does not report. Events stream to editors as `file-changed {path, sha}`. |
| 03.6 Any-site | `velora studio --site <url> --edit [--scene] [--read-only]` starts the bridge in the studio process with the studio origin as the only allowed Origin, and prints the `/__velora/` editor URL. |
| 03.7 Skill | New `skills/velora-editor/SKILL.md` (dry-run → `--write` loop, `--expect-sha` etiquette, track shorthand, op table, exact undo). Added to the router, `VELORA_SKILL_NAMES`, `check-skills` and the lock. |

## Evidence
- `tests/core/json-format.test.ts` (7): no-op byte identity over the whole Phase 00 corpus (38 files) × LF/CRLF/BOM/BOM+CRLF variants plus 4-space, tab and inline fixtures; one changed keyframe changes exactly one line in every corpus recipe; key order and canonical insertion; snapshot bytes untouched; CRLF, BOM and no-trailing-newline preserved on edit; shortest numbers.
- `tests/core/edit.test.ts` (11): **400 random op batches over the corpus**. Each is rejected atomically or yields a schema- and preview-valid recipe; the input is never mutated; `apply(inverse(apply(x)))` deep-equals `x`; on disk the undo is byte-identical when formatted with the pre-edit text as reference (what the bridge history does). Without a reference, the plain reformat is exact in over 90% of cases (asserted). Also covers auto node insertion, the duration guard and hint, atomicity and op attribution, node and last-key refusals, clip create/update/dissolve/bake, `path.fromAxes`/`path.tangent`, unsupported ops, coalescing, labels, shorthand and diff.
- `tests/cli/edit.test.ts` (4): dry run leaves the file unchanged; `--write` writes once (one added line); undo through the printed inverse restores bytes; stale `--expect-sha` gives `ERR_EDIT_CONFLICT`; stdin batches; op attribution; ls with evaluated values; shorthand and usage errors (exit 1 and 2); help.
- `tests/project/bridge.test.ts` (9): the hello/read/edit/conflict/undo round trip; audit log without the token; `file-changed` events for external writes; token missing, wrong or in the query; foreign and missing Origin; preflight; Host rebinding; oversized body, too many ops, wrong content type; traversal, symlinked scene (where the OS allows creating one) and read-only; non-loopback binds refused; token only in the URL fragment; idle shutdown.
- **Validation on `local-project` (a copy of its recipes):** `velora edit key --scene overview --track camera.z --at 1200 --value 400 --ease cubic.out --write` added one keyframe (+5 lines, in that file's multi-line style). `velora edit apply --ops <inverse> --write` restored the file **byte-identically** (SHA-256 equal).

## Not verified / deviations
- **HMR step of the validation criterion** (the open studio updating after `--write`) was not re-run here; it is the same recipe-file HMR path the existing `test:iterate` gate verifies. **`studio --edit`** is type-checked and shares `startSceneBridge` with the tested bridge, but was not run end to end (it needs the managed studio workspace).
- **Bridge security suite on Linux and macOS:** run on Windows only so far; it needs the CI matrix.
- **Byte-exact undo in the CLI:** exact whenever the edited file still contains a node of each restored shape (the common case, and the local-project run). When an edit deletes every node of a shape (for example the only track), the CLI undo restores the value in default layout; the bridge, which keeps history, is always exact.
- **`restore`** is an added op (the inverse primitive), addressed by track, node, clip, link or a fixed set of recipe fields.
- The watcher covers compositions and presets now; the bridge serves only scene files until Phases 07 and 10 add `/v1/presets` and `/v1/compositions`.
- `docs/product.md` and `docs/architecture.md` still say "the studio writes no files"; Phase 04 updates them when Edit mode ships, as the plan requires.
