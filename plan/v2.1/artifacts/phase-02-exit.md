## What shipped
| Task | Implementation |
|---|---|
| 02.1 Clips | `motion.clips[]` (`MotionClipSchema`, recursive, nesting ≤ 4): `startMs`, `speed`, `inMs`/`durationMs` trim, `loop` (play count), group `ease` (per loop), `mode` replace/add, `label`, `source` provenance. Local time = `inMs + ease((t − startMs)·speed / span)·span` (exact `inMs + within` without an ease). Holds local 0 before the clip and the end after it. Clips flatten once per compiled motion into virtual tracks with composed time maps. Validation: unique ids, depth, clip end ≤ `durationMs`, **one replace owner per property** (the message names both owners), and no color tracks in add clips. |
| Additive mode | Add values sum onto the replace owner. Without an owner they go to `MotionState.additive` (`surfaces`/`camera`/`focus`), and consumers apply them to the static base with `withAdditive` (React `Scene`, `framingReport`, `projectPoints`). Channel and style adds without an owner use base 0. |
| 02.2 Staggers | `members` (≤ 256) plus `stagger {eachMs, order, ease?}`; tracks target `{kind:"surface", id:"$member"}`. Orders: forward, reverse, center-out, edges-in, `{random: seed}` (`createRng`, Fisher–Yates). Offset = `ease(position)·eachMs·(n−1)`. Each member becomes a virtual sub-track (`clips.0.tracks.0[2]` in diagnostics). `createCascadeClip` (new owner) evaluates equal to `createCascadeTracks`, which is unchanged. |
| 02.3 Paths | `property: "position"` for surface and camera targets, with `[x,y,z]` keyframes plus optional `inTangent`/`outTangent` offsets. `src/core/paths.ts`: cubic Bézier per segment, Catmull–Rom auto handles, fixed 64-sample arc-length LUT. Keyframe easing maps time to distance (`"auto"` means linear distance). `rove` gives constant speed over the whole path. `orient {axis: yaw\|yaw-pitch, offsetDeg}` derives `rotateY` (`atan2(dx, dz)`) and `rotateX` (`atan2(−dy, \|dxz\|)`). A path owns x/y/z (and the oriented rotations), so explicit replace tracks on them are rejected. Smooth interpolation, track ease and noise are rejected. Advice: `path-speed-spike` (segment speed ratio > 4 without rove). |
| 02.4 Links | `motion.links[]` (≤ 256): `{to, from: TrackRef \| {channel}, scale, offset, delayMs, mode}`, with `to(t) = from(t − delayMs)·scale + offset`. Evaluated per slot with recursion for delays. Validation: cycles (named, for example `surface a.x -> surface b.x -> surface a.x`), chain depth ≤ 8, one link per target, and replace links count as owners. No expressions. |
| 02.5 Constraints | `scene.constraints[]` (≤ 16, `SceneConstraintSchema`): `lookAt` and `focusFollow` with `{surface, anchor?}` or `{point}` targets and `weight` (0..1 or a channel TrackRef). React `Scene` takes a `constraints` prop and drives the stage from the resolved camera; `ScenePreview` and `CompositionPlayer` pass recipe constraints. `shots.ts` now uses the spatial owner's `cameraMatrix`, and `framingReport`/`projectPoints` honor constraints. |
| 02.6 Rigs | `buildOrbitRig` (new owner) returns `{clip, constraint}`: a rove camera position path sampled every `stepDeg`, eased as a group, plus rotation hints and a lookAt. Existing shot kinds are unchanged (template certification green). |
| 02.7 Schemas, guide, skills | `scene-recipe.schema.json` regenerated (recursive clips export fine). Guide capabilities: `clips`, `positionPaths`, `links`, `constraints`; the guide's track table now merges properties per target (includes `position`). ## Deviations and findings
- **lookAt is a pan/tilt about the camera's eye.** Under the stage convention, camera rotation pivots about the stage origin, so rotation alone cannot center every target (for example a target at the origin with camera x = 200). lookAt therefore derives the eye from the authored camera, solves rotateX/rotateY (closed form, in front, nearest the authored angles), and **re-derives camera x/y/z** so the eye stays fixed. Weight 0 returns the authored camera exactly.
- **Constraint `weight` accepts a number or a channel TrackRef**, not any TrackRef. Any property can drive a channel through a link.
- **A link reading a property with no track gets 0** (the static base is not known to the motion evaluator).
- **Performance:** the slot-based evaluator costs about 373 µs per cached call at 300 tracks (Phase 01: 222 µs; baseline 381,114 µs). The jsdom scrub step is 32 ms (Phase 01: 17 ms). Both runs were on a loaded machine. Still about 1,000× over the Phase 00 baseline; Phase 11 sets the budgets.
- `reviewAuthoring` now checks clip, stagger and link surface targets (`unknown-surface`). The plan's "lookAt target outside the frame at a sampled time" advisory is not implemented: centering is exact by construction, and an unreachable target cannot occur with the eye-based solve.
