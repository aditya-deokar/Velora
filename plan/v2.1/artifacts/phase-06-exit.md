# Phase 06 exit report: viewport, direct manipulation and camera tools

Date: 2026-11-16. Branch `feat/v2.1-motion-graphics-suite-plan`, on top of `f56799a` (Phases 04–05).
Machine: Windows 11 (win32-x64), Node 24.12.0, Playwright Chromium 1208.

## What shipped
| Task | Implementation |
|---|---|
| 06.1 Projection owner | `src/core/spatial.ts` owns `projectWorld(camera, frame, point, space)` (the one forward projection, stage or view space, `depth = perspective − z`), `screenRay` (eye through a frame pixel; view or stage space), `intersectPlane(ray, world)` (local `u, v` and `t` on a matrix's z = 0 plane, Cramer solve, null when edge-on or behind) and `surfaceQuad(node, camera, frame)`; plus the helper `invertAffine`. `shots.ts:projectPoints` now calls `projectWorld` (goldens byte-identical). The checker registers the four owners. `camera.zoom` (14.2) does not exist yet; Phase 14 extends these functions under the same round-trip tests. |
| 06.2 Picking | `src/editor/viewport/picking.ts`: Surface quads from the Scene snapshot's world matrices and measurements, nearest first; even-odd point-in-quad; Alt+click cycles the stack; group scope (double-click enters, Esc leaves; a group's ancestor at the scope is selected); marquee (bbox + polygon overlap); Shift adds, Ctrl/⌘ toggles; locked and hidden layers (and their children) are skipped. The overlay (`Overlay.tsx`) is a chrome-marked SVG in frame pixels in the ScenePreview overlay slot, with outlines and handles at constant screen size. |
| 06.3 Gizmos | **Move (V):** `MovePlane.ts` intersects the cursor rays with the parent plane at the layer's z, so the grabbed point follows the cursor under perspective; axis handles; depth handle (z push); Shift 10 px; guide snapping (center, thirds, 5 %/10 % safe lines) of the projected center, solved back to the plane. **Rotate (R):** rotateZ follows the cursor angle (unwrapped across ±180°), X/Y rings by drag; Shift snaps the value to 15°. **Scale (S):** corners scale uniformly about the opposite corner with position compensation, Alt about the pivot, side handles write scaleX/scaleY. **Pivot (P):** writes originX/originY and compensates x/y (and z under rotation) in one batch. Numeric entry during a drag (digits, Enter); Esc restores the pre-drag draft. Every value goes through `intentToOps`. |
| 06.4 Motion paths, onion skin | `MotionPath.ts` samples the selected layer's evaluated center at up to 30 fps across the work area (or scene) through the compiled evaluator, with the current viewpoint pinned, and draws a polyline with ticks; keyframe dots at x/y/position keys are draggable (`key.set` on those tracks); position-path tangents are drawn. **Convert to position path** command (`path.fromAxes`). `OnionSkin.ts` returns ghost quads at ±N frames (no second DOM render). |
| 06.5 Camera tool (C) | `CameraTool.ts`: orbit (around the selected layer or focus point; the pivot keeps its view position), truck/pedestal (content follows the cursor), dolly (wheel, Alt+vertical drag), pan/tilt in place (Ctrl/⌘, eye fixed), roll ring, lens (Alt+wheel through `lens.ts`), dolly-zoom (Alt+Shift+wheel, closed form `depth' = depth·P'/P` checked against `projectWorld`). Writes keys when animated or Auto-key, else `camera.set`. |
| 06.6 Director view (Tab) | `Scene` gains an editor-only `viewCamera` prop: a second `evaluateScene` of the same nodes from the director camera, with no constraints and depth of field off, drives the display; snapshots keep the real camera (`camera`, `focus`) and add `view`. `ScenePreview` takes `viewCamera` (editor layout) and marks the capture viewport `data-velora-view="director"`; `useSceneCapture`'s verify throws "Return to camera view before exporting.". The overlay draws the real camera (eye, frustum to the frame plane, translucent focus plane, camera path); dragging the eye moves the real camera (`DirectorView.dragCamera`). Camera-tool drags navigate the director viewpoint (UI state only). A badge says depth of field is off. |
| 06.7 Focus tool (F) | `FocusTool.ts`: click → `focus.distance` = the clicked point's depth for the **real** camera (also from the director view); Shift+click → `constraint.set focusFollow` with the clicked anchor. **Rack focus** command (two layers) → two `focus.distance` keys with a cinematic ease that land sharp (< 0.5 px by `sampleFocus`). Peaking turns on while the tool is active (`ScenePreview` `peaking`). |
| 06.8 Lock/solo | Locked layers are not pickable; solo keeps the Phase 04 editor-only dimming. |
| Shortcuts | `tool.move` V, `tool.rotate` R, `tool.scale` S, `tool.camera` C, `tool.focus` F, `tool.pivot` P, `view.director` Tab (only from the viewport or the page body, so Tab still moves focus in panels), plus `view.onion`, `view.paths`, `path.convert`, `focus.rack` in the palette. None collide with transport keys (commands test). |

- **Unit:** `tests/core/projection.test.ts` (7: 500 random cameras and transformed planes with scale and skew round-trip `projectWorld → screenRay → intersectPlane` within 1e-6; stage/view agreement; behind-eye and edge-on refusals; `surfaceQuad`; `invertAffine`; `projectPoints` equals `projectWorld`). `tests/editor/picking.test.ts` (6: depth order, perspective hit edges, Alt-cycle, locked/hidden skip, group enter/exit, marquee and modifiers). `tests/editor/viewport.test.ts` (15: perspective-correct move incl. depth scaling, axis/Shift/guide snapping, intent semantics, rotate snapping, opposite-corner scale and pivot compensation under rotation (< 0.01 px), orbit/pan/truck/dolly invariants, dolly-zoom width within 1 % with background warp, director gizmo and eye drag, focus depth, rack focus sharp at both ends, motion-path samples and key dots, onion skin).
- **Browser** (`tests/browser/viewport.spec.ts`, 5/5, real bridge): click selects the dashboard in the frame and a 100 px drag writes x within ±0.5 px of 100 / frame scale; Shift ring rotation writes a 15° multiple; a pivot drag leaves the rotated layer's box within 1 px; Alt+Shift+wheel dolly-zoom changes the lens and keeps the subject width within 1 %; director view refuses capture with the documented message and a gizmo drag edits the real camera; a focus click makes the layer sharp (`data-velora-blur` < 0.5). The move and rotate/pivot journeys also assert that the file bytes equal a headless replay of the accepted op batches (`applyEdits` + `formatJsonDocument`, the `velora edit apply` path).
- **Suites:** core/react/editor/preview 1,026 tests pass (four preview/bridge tests time out at 5 s only under full parallel load on this machine and pass when run alone, the known Windows issue); architecture 177/177; goldens match; typecheck clean; `check-skills` green; browser 36/36 after one Phase 04 journey step changed (it clicked empty viewport space to leave a text field, which now deselects the layer, so it clicks the layer row instead).

## Not verified / deviations
- **Gizmo budget** not met (above).
- **Viewport zoom/pan** (Space-drag, middle-drag) is not implemented: Space is the transport play key and the frame scale belongs to ScenePreview. The overlay works at the contained frame scale.
- **Scale axis handles** scale about the pivot (no opposite-edge compensation); only corners compensate.
- **Motion-path dots** cover root x/y/position tracks; clip tracks (shifted by their clip) are edited in the timeline. Position-path tangents are drawn but dragging them is not wired (`path.tangent` remains available to the CLI and inspector).
- **Orbit with a lookAt constraint** edits the authored camera; the constraint re-aims afterwards, so the result can differ from the drag preview.
- **"No editor overlay pixels in exported frames"** relies on the Phase 04 mechanism (captures load the stripped preview URL; every overlay element is chrome-marked). No new SHA comparison between Preview and Edit captures was run.
- Picking does not yet include depth layers or anchors (Phases 13/15) and has no `camera.zoom` (Phase 14).
