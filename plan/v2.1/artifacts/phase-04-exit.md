## Evidence
- **Journey** (`tests/browser/editor-shell.spec.ts`, real in-process bridge plus temp project, Chromium): open the editor URL (fragment stripped) → select `dashboard` → stopwatch on `x` → Shift+→ ×2 to 2 s → type 120 → the file on disk is **byte-equal** to the expected formatter output → Ctrl+Z ×2 → the file is **byte-identical to the original** → an external write is adopted and the next edit lands on top of it. **Time to first keyframe on disk: 1,477 ms** (README §8 target ≤ 60 s). Also: the copied export command contains neither `velora-edit`, the fragment nor the token; read-only mode keeps edits in memory and offers the command.

- **Suites:** core, React, editor and preview 987/987; CLI, project and docs green after the README example fix; browser 31/31; architecture 176/176 (owners `createEditorStore`, `intentToOps`, `EDITOR_COMMANDS`, `useSceneInspector`); goldens match; typecheck clean; `check-skills` green.

## Not verified / deviations
- **Hosts:** the journey runs on the repository's Vite test host (React 19) with an in-process bridge, not on the three installed fixture hosts (Vite, Next App Router, Next Pages/React 18) the plan lists. Those need fixture hosts with `velora edit --no-open`; that remains a Phase 11 gate.
- **Browser coverage:** the bridge is now exercised from a real browser page in Chromium (CORS preflight, Authorization, streaming events: the Chromium half of spike S2). Firefox and WebKit are still untested.
- **"Stopwatch on" for one-keyframe tracks** is editor UI state (armed): a one-keyframe track counts as a static override unless its stopwatch was switched on in this session. The recipe has no field for it.
- **Brand easing** and **saved user curves** are not shown in the easing library: the editor cannot read `velora.brand.json` yet, and saving needs the Phase 07 presets endpoint.
